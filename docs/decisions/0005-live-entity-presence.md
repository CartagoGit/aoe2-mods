# ADR 0005 — Live entity presence in the reference profile

Status: reference contract for i00005/S1; native observation and AoE2 QA remain pending i00005/S2. The design dossier's `implementationStatus=unimplemented` remains accurate and is not an executable DSL operation.

## Decision

The version 1 scenario source envelope remains unchanged. The optional composed profile remains schema version 2 and adds a strict `current-entity-presence` requirement with original entity IDs, exactly one assigned destination per identity and a feasible `requiredCount`. This predicate evaluates live observed status and current zone membership. It does not read the historical `arrivedEntities`, `arrivalLedger`, receipt facts, or exported ledgers. A previous arrival remains true after movement or death; it cannot certify residence.

The reference observer input is a typed `LiveSpatialBatch` with a monotonically increasing safe integer `sequence` and an array of `{entityId, alive, zones}` observations. A batch replaces the entire current observation map. Omitted identities become unknown. An observed actor may occupy overlapping zones, but counts only once and only at its own assigned destination. An alive actor outside its assigned zone does not count. An actor marked dead must have no memberships, becomes irreversibly destroyed in the reference state, and cannot be revived by a later batch. Unknown entity or zone IDs, duplicate identities or memberships, malformed values, inconsistent death status and stale sequences reject the entire batch. The reducer does not infer zone membership from district names and offsets: a future native observer must compute it from calibrated current positions and a defined collision policy.

The snapshot stores the last sequence and canonical current observations separately from history. Presence profiles initialize those fields; profiles without the new requirement retain their previous serialized shape and fingerprint. Old profile snapshots still parse and run. The changed requirement changes the existing contract fingerprint, so a snapshot from another contract cannot be loaded silently. A saved positive observation is never sufficient for a latch or terminal victory: `latch-objective` requires a fresh batch when its objective has presence; `tick` and `enter-phase` require a further fresh batch when a victorious objective depends on latched presence. The latter rechecks those requirements after the batch has replaced positions and applied deaths. Irrecoverable loss and explicit defeat keep priority. Missing or invalid evidence blocks the attempted completion, without inventing an automatic defeat.

The standalone observation action supports reversible movement between closure attempts. A payment, `record-arrival`, `record-predicate`, elapsed time, prior latch or stored Boolean cannot replace the fresh batch. The sequence is monotonic across save/load. Input snapshots are parsed and new states are returned without mutating the caller's object.

## Scope and consequences

This is a deterministic reference rule and compiler gate. The native renderer and Python exporter still reject composed profile v2 as `capability-not-implemented`. i00005/S2 must build and test real spatial/health observation on top of the i00003/S3 native foundation, including same-tick ordering, save/load and actual game QA. i00005/S3 may then update dossier support and promotion gates. This decision does not create physical custody, carried inventory, ownership transfer, movement freeze or historical geography certification, and does not change approved i00003/S1 receipt semantics or campaign IDs.
