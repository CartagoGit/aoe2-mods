# Instrucciones del proyecto

La fuente de verdad operativa de DelendAI es el servidor conectado: consultar su overview y descubrir capacidades actuales antes de modificar propuestas, reclamar trabajo, registrar revisiones o integrar cambios. No copiar ni reimplementar su sistema. Seguir el bootstrap servido por la versión instalada; las instrucciones del usuario prevalecen.

Lee README.md, docs/production/plan.md, docs/architecture/overview.md, docs/standards/naming.md y los documentos de traspaso. Recupera estado del repositorio y DelendAI, no del recuerdo del chat.

El checkout compartido sigue develop. Trabaja exclusivamente en la unidad aislada abierta por DelendAI. Declara tu identidad real en DELENDAI_AGENT_ID antes de llamadas Git/CLI. No hagas commits, resets, cambios de rama ni pushes manuales de develop. Integra mediante la publicación oficial y su gate. Un rechazo se registra y se conserva el trabajo.

No cambies contratos, rangos de cadenas o identidad de campañas para resolver un problema de contenido. Si una operación del adaptador no existe, registra un requisito de infraestructura y no la emules como funcional. No atribuyas citas inventadas, voces auténticas ni pruebas de juego inexistentes.

Antes de entregar: bun run validate y bun run test:export cuando afecte al adaptador. Toda revisión independiente pendiente queda explícita; el implementador no aprueba su propio slice. No distribuir mods ni hacer generación pagada masiva sin autorización específica. No generar campañas históricas completas durante el encargo de infraestructura.
