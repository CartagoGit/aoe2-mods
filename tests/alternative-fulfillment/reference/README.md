# Alternative fulfillment reference tests

These are technical fixtures for the opt-in fulfillment profile and its reference reducer. Profile schema version 3 is explicitly opt-in. Its source envelope remains version 1, and its snapshot nests the existing version 2 core as a reuse boundary; this is not a migration of version 2. The version 3 fingerprint covers the complete version 3 profile. Tests compare the projected version 2 core/fingerprint behavior with the existing core contract rather than treating the wrapper as a replacement.

The reference bounds a plan to at most 8 services, 8 recipes per service, and 4096 service/recipe combinations. It also limits an observed actor to one zone per live batch, requires distinct workers across services, and restricts each v3 optional objective to at most one leading entity-arrival predicate because shared v2 arrival receipts use filtered indices. V2 receipts remain unchanged. These are conservative reference limits, not claims about Age of Empires II or a native adapter. Save-load creates a fresh input-context epoch so a host can discard queued pre-load inputs; this does not establish native UI support or host integration.

The artificial fixture keeps abstract zone coordinates within 256 × 256 tiles and separates its work and reception footprints. They are test coordinates only: the reference does not calculate pathfinding, slope, terrain, or physical access.

The fixture reads main recipe costs and operating stock from `docs/research/odyssey-research/imperial34-care-allocation-plan.json`; optional reserves, costs, and rewards come from `docs/qa/alternative-fulfillment/decision/portfolio-matrix.json`. Thus these test values follow the current accounting sources instead of duplicating their numbers in the fixture. The 95 financial rows are derived accounting expectations. The test suite also runs those 95 portfolio combinations through artificial reference actions, plus 27 affordability trials and 24 before-funding witnesses. These executions are not physical scenarios or gameplay validation. They use artificial identities and observations and do not establish historical geography, terrain, unit pathing, physical feasibility, interface quality, fun, balance, or gameplay certification. Optional objectives use distinct arrival, visit, health, and payment mechanics; their fixture effects remain reference behavior only.

Additional negative cases exercise malformed or partial selections, unknown recipes, non-integer/unsafe/overflowing costs, plan bounds, shared workers, generation-input cycles, stale spendable previews, protected/reward-reserve isolation, payment-before-reward, duplicate optional awards, cancellation/refund, committed-plan immutability, and output/recipient loss. Save-load cases cover valid lifecycle checkpoints and corrupted escrow, profile cost/destination/version fingerprints, stale epochs, and optional completion receipts without predicate evidence. Zero-cost recipes still require reserve, commit, departure and work before output. These are reducer reference tests; the 95 finance rows are not 95 independent game or pathfinding tests.
